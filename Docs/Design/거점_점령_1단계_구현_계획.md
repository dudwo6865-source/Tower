# 거점 점령 1단계 구현 계획

작성일: 2026-10-28

기준 기획: [신규 미션과 거점 점령 기획](신규_미션과_거점_점령_기획.md)

현재 코드를 확인해 작성한 구현 계획입니다. 아래 신규 컴포넌트·필드 이름은 제안이며 아직 구현되지 않았습니다.

## 1. 이번 구현의 목표

플레이어가 표시된 거점 하나로 유닛을 이동시켜 일정 시간 머무르면 승리합니다. 첫 점령 경험에 집중합니다.

- 살아 있는 플레이어 유닛이 범위 안에 있고 적이 없으면 점령이 진행됩니다.
- 초기 점령 시간은 5초로 제안하며 스테이지에서 조절합니다.
- 적이 들어오면 진행을 멈추고, 적이 없어지면 이어서 진행합니다.
- 아군 유닛이 모두 나가거나 사망하면 진행도를 0으로 되돌립니다. 적과 아군 부재가 겹치면 초기화를 우선합니다.
- 아군 건물만으로는 점령하지 못합니다. 유닛 수에 따른 점령 속도 보너스도 없습니다.
- 점령을 완료하면 기존 결과 창과 클리어 보상 흐름으로 승리합니다.
- 본부 파괴 시 패배합니다. 같은 프레임의 점령 완료보다 본부 파괴를 우선합니다.
- 일시 정지 중에는 진행하지 않고, 게임 종료 후에는 상태를 바꾸지 않습니다.

방어 타이머, 이탈 유예, 전용 반격, 중립 소유권 이전, 복수 거점, 보스와 타임어택은 이번 구현에 포함하지 않습니다.

## 2. 기존 구조와 연결 방침

현재 MapConfig의 승리 조건을 MapLoader가 GameResultManager에 전달합니다. GameResultManager는 생존·스포너 파괴 중 활성화된 조건을 먼저 달성하면 승리시키고, 결과·통계·보상을 함께 처리합니다. VictoryConditionHUD는 이 매니저의 설정을 읽어 목표를 표시합니다.

이 흐름에 점령 조건을 추가합니다. 기존 스테이지 데이터를 일괄 변환하거나 새 미션 시스템으로 교체하지 않습니다. 신규 점령 사용 값의 기본은 꺼짐으로 두어 기존 스테이지 동작을 유지합니다.

점령 전용 스테이지에서는 점령 승리만 켜고 기존 두 승리 조건은 끕니다. 다른 승리 조건도 켜면 기존과 같이 어느 하나를 먼저 달성해도 승리하며, 에디터에 이 사실을 경고합니다. 설정을 몰래 변경하지 않습니다.

## 3. 설정값을 둘 위치

### MapConfig — 스테이지 규칙

추가할 인스펙터 항목:

- `거점 점령 승리 사용`: 기본 꺼짐.
- `점령 시간(초)`: 기본 5초, 0보다 커야 합니다.

기존 `승리 조건 덮어쓰기`를 그대로 따릅니다. GameResultManager에도 같은 설정을 두어 MapLoader 없는 테스트 씬에서는 직접 설정할 수 있게 합니다. 덮어쓰기가 켜졌을 때는 MapConfig 값이 기준입니다.

### 신규 CapturePoint — 맵의 목표 위치

맵 프리팹의 MapRoot 아래에 빈 오브젝트를 만들고 붙이는 컴포넌트로 제안합니다.

- `거점 이름`: 목표 안내에 사용할 이름.
- `점령 반경`: 월드 단위의 원형 범위. 0보다 커야 합니다.
- 오브젝트 위치: 원의 중심. 별도의 좌표 필드는 만들지 않습니다.

점령 시간은 MapConfig에만 두고 거점에 중복 저장하지 않습니다. 플레이어 ID는 GameResultManager의 기존 `플레이어 ID`를 사용합니다.

Scene 뷰에서 실제 판정 반경과 같은 기즈모를 표시합니다. 판정 반경은 오브젝트 스케일과 무관한 월드 단위로 정의해 부모 스케일 때문에 의미가 달라지지 않게 합니다.

### 목표 연결

MapLoader가 맵을 준비한 후 CurrentMap 아래의 활성 CapturePoint를 찾고 GameResultManager에 명시적으로 연결합니다. MapConfig 에셋에서 씬 오브젝트를 직접 참조하지 않습니다.

- 점령 사용 시 활성 거점은 정확히 하나여야 합니다.
- 0개이거나 여러 개이면 명확한 오류를 남기고 점령 판정을 시작하지 않습니다. 임의의 첫 거점을 고르거나 자동 승리하지 않습니다.
- MapLoader의 Replace와 UseSceneMap 모두 실제 사용 중인 맵 안에서 찾습니다. 제거 중인 이전 맵을 검색하지 않습니다.
- MapLoader 없는 씬은 GameResultManager의 `점령 거점` 참조를 직접 연결합니다.
- 준비 전에는 타이머를 돌리지 않습니다. 재시작·맵 교체 시 참조와 진행도를 초기화하고 이전 이벤트 연결을 해제합니다.

## 4. 점령 판정과 상태

신규 CapturePoint가 범위와 점령 진행을 관리하고, GameResultManager가 승패를 확정하도록 역할을 나눕니다. 상태는 `대기`, `점령 중`, `적 때문에 중단`, `완료`로 충분합니다. 설정 오류는 플레이 상태와 구분해 안내합니다.

판정에 기존 SelectableRegistry.Entities, SelectableEntity.ownerId·entityType, EntityHealth.IsAlive를 활용합니다. Collider 진입 이벤트에만 의존하지 않아 여러 콜라이더, 범위 안 사망, 비활성화에서 개체 수가 틀어지는 문제를 피합니다.

- 활성 상태이며 체력이 있는 생존 개체만 셉니다. 시체·비활성 오브젝트·배치 미리보기는 제외합니다.
- 아군 점령자는 플레이어 ID가 같은 Unit만 인정합니다.
- 방해자는 상대 소유자의 살아 있는 Unit 또는 Building입니다. 현재 TargetFinder는 다른 ownerId를 적으로 판정하므로 1단계도 그 규칙을 따릅니다. 이번 맵에는 중립 개체를 넣지 않으며, 중립 도입 전에는 적대 관계 판정을 별도로 확장해야 합니다.
- 개체 중심과 거점 중심 사이의 XZ 평면 거리로 판단하며 경계는 포함합니다. 건물은 배치 중심을 사용합니다.
- 위아래 층이 겹치는 위치는 첫 거점에 사용하지 않습니다. 높이 구분 판정은 이번 범위에 넣지 않습니다.
- 안개에 가려져 렌더러가 꺼져도 실제 살아 있는 적은 점령을 방해합니다.
- 아군이 없으면 진행도 초기화, 아군과 적이 함께 있으면 진행도 유지·정지, 아군만 있으면 진행합니다.

단일 거점에서는 등록된 개체를 한 번 순회해 판단하는 단순한 방식으로 시작합니다. 매 프레임 씬 전체 검색이나 임시 목록 생성을 피하고, 실제 개체 규모에서 비용을 확인한 뒤 필요할 때 공간 검색을 도입합니다.

GameResultManager가 점령 갱신을 호출하는 흐름을 명확히 정해 초기화 순서나 Update 순서에 기대지 않습니다. 시간 누적에는 게임 시간을 사용하고 일시 정지 때는 판정 갱신도 멈춥니다.

### 승패 확정 순서

점령 완료 콜백에서 바로 EndGame을 호출하지 않고 완료 요청을 기록합니다. 해당 프레임의 피해·사망 처리가 끝난 뒤 본부 생존을 재확인하고 승리를 확정합니다. 단순히 먼저 호출된 결과를 고정하면 동시 파괴 우선 규칙을 지킬 수 없습니다.

실제 피해 처리 시점을 확인해 결과 확정 단계를 정하고 동시 발생 사례를 검증합니다. 본부가 아직 생성되지 않았거나 연결되지 않은 상태를 살아 있는 것으로 간주해 승리시키지 않습니다. 종료 처리는 한 번만 호출해 보상 중복을 막습니다.

## 5. 목표 표시와 외형

VictoryConditionHUD에 `점령 조건 텍스트`, `점령 조건 묶음` 참조와 상태별 문구를 추가합니다. 기존 전체 패널 숨김 조건도 세 가지 승리 조건을 모두 고려하도록 변경합니다.

표시 예시:

- 대기: “전초 지점을 점령하세요. 유닛을 구역 안으로 이동하세요.”
- 진행: “전초 지점 점령 중 · 3 / 5초”
- 적 존재: “적 때문에 점령이 중단되었습니다. 구역 안의 적을 제거하세요.”
- 이탈 후: “아군 유닛이 없어 점령 진행이 초기화되었습니다.”
- 설정 오류: “점령 목표 설정을 확인하세요.”

TMP 텍스트와 묶음 오브젝트, 월드의 거점 표시물은 사용자가 에디터에서 만들고 연결합니다. 코드로 패널·텍스트·링을 자동 생성하지 않고 외형·위치·색·폰트·크기를 덮어쓰지 않습니다. UI 연결이 없어도 게임 판정은 동작하고 누락은 안내합니다.

첫 버전의 월드 표시는 편집한 원형 표시물과 깃발 등으로 구성하고, Scene 기즈모를 기준으로 표시물 크기를 실제 반경에 맞춥니다. 목표 위치 안내는 시작부터 보여주되 주변 적의 안개를 걷지는 않습니다. 플레이 중에도 목표 표시물이 식별되는지 확인합니다.

## 6. 예정 파일과 변경 내용

- 신규 `Assets/Script/Mission/CapturePoint.cs`: 범위, 점령 상태·진행도, 초기화와 기즈모. 신규 폴더·스크립트의 Unity 메타 파일도 포함합니다.
- `Assets/Script/Map/MapConfig.cs`: 점령 사용 여부와 점령 시간 추가.
- `Assets/Script/Map/MapLoader.cs`: 점령 설정 전달, 실제 로드한 맵의 거점 검증·연결.
- `Assets/Script/GameResultManager.cs`: 점령 설정·참조, 초기화와 갱신, 완료 요청의 승패 처리.
- `Assets/Script/UI/VictoryConditionHUD.cs`: 점령 상태 표시와 전체 패널 활성 조건 확장.
- `Assets/Script/Editor/StageEditorWindow.cs`: 승리 조건 항목, 미리보기, 조건 없음·혼합 조건·잘못된 시간 경고 수정.
- `Assets/Script/Editor/StageEditorWindow.Wave.cs`: 스테이지 요약에 점령 조건 반영, 관련 검증 문구 확인.
- 테스트용 MapConfig·맵 프리팹: 기존 스테이지를 바꾸지 않도록 별도 테스트 구성 사용. 실제 경로는 구현 시 기준 맵을 확인해 정합니다.
- 설정 안내 문서: 실제로 구현한 컴포넌트 이름과 연결 순서, 테스트 결과를 기록합니다.

인스펙터 필드에는 한국어 Label을 붙이고 설명·경고도 한국어로 작성합니다. 커스텀 에디터는 GUIContent로 한국어 라벨을 직접 전달합니다.

## 7. 구현 후 유니티 설정 순서

1. 테스트용 스테이지를 선택하고 `Tools > 맵 > 스테이지 에디터 > 승리 조건`을 엽니다.
2. `승리 조건 덮어쓰기`와 `거점 점령 승리 사용`을 켜고 생존·스포너 전멸 승리는 끕니다.
3. `점령 시간(초)`을 5초로 설정합니다.
4. 해당 맵 프리팹의 MapRoot 아래에 거점 오브젝트를 하나 배치하고 CapturePoint를 붙입니다.
5. 거점 이름과 반경을 정하고 NavMesh로 접근 가능한 위치인지 확인합니다. 범위 안에 영구적인 적 건물이 남지 않게 배치합니다.
6. 월드 표시물을 배치해 범위와 위치를 보여줍니다. 반경 기즈모와 외형을 맞춥니다.
7. 기존 목표 UI에 TMP 텍스트를 추가하고 VictoryConditionHUD의 점령 참조에 연결합니다.
8. MapLoader가 테스트용 MapConfig를 사용하는지 확인하고 실행합니다.

## 8. 완료 기준과 검증

핵심 판정은 아군 수·적 수·경과 시간을 입력으로 검증할 수 있도록 분리합니다. 가능한 기존 테스트 환경에서 상태 전이를 검증하고, 시야·맵 로드·UI·보상은 실제 플레이로 확인합니다.

- 아군 유닛 하나가 5초 머물면 한 번만 승리하고 기존 결과 창·클리어 보상이 정상 동작합니다.
- 아군 건물만 있거나 범위 밖 유닛만 있으면 진행하지 않습니다.
- 여러 아군이 있어도 5초가 필요합니다.
- 2초 진행 후 적 진입 시 2초에서 멈추고 제거 후 남은 3초를 진행합니다.
- 마지막 아군 이탈·사망 시 0으로 초기화하며 다시 진입하면 처음부터 진행합니다.
- 여러 콜라이더를 가진 개체, 사망 후 남은 시체, 비활성 개체를 잘못 세지 않습니다.
- 경계 위치와 화면상 표시 범위가 일치합니다.
- 일시 정지·재개에서 시간과 상태가 튀지 않습니다.
- 점령 완료와 본부 파괴가 같은 프레임이면 패배합니다. 본부 생성 전에는 승리하지 않습니다.
- 거점 누락·중복·잘못된 반경·시간을 안내하며 잘못된 상태에서 자동 승리하지 않습니다.
- Replace·UseSceneMap·씬 직접 연결·재시작에서 참조와 진행도가 올바릅니다.
- 점령만 사용하는 경우 목표 UI 전체가 숨겨지지 않습니다.
- 기존 생존·스포너 전멸 스테이지의 승리 및 결과 처리가 유지됩니다.

## 9. 권장 구현 순서

1. 점령 상태와 범위 판정, 초기화 규칙을 구현합니다.
2. 스테이지 설정·맵 연결·승패 흐름을 통합합니다.
3. 스테이지 에디터와 기존 목표 HUD를 확장합니다.
4. 별도 테스트 맵에 거점을 배치하고 외형·UI를 연결합니다.
5. 완료 기준을 확인하고 에디터 설정 안내를 마무리합니다.

첫 구현 완료는 위 1단계 흐름이 실제 스테이지에서 동작하는 시점입니다. 방어와 중립 전력 획득은 별도 후속 작업으로 진행합니다.
