# 거점 점령 미션 설정

## 구현된 규칙

거점 하나에 살아 있는 아군 유닛이 있고 적이 없으면 점령 시간이 흐릅니다. 적 유닛·건물이 들어오면 진행을 보존한 채 멈추며, 아군 유닛이 모두 사라지면 진행도를 초기화합니다. 아군 건물만으로는 점령할 수 없습니다. 여러 유닛을 보내도 속도는 같습니다.

점령 완료 후 기존 미션 성공·보상 흐름으로 이어집니다. 완료한 프레임에 본부도 파괴되면 패배합니다. 일시 정지 중에는 진행하지 않습니다. 방어 시간·중립 전력 획득은 아직 포함하지 않습니다.

## 테스트 스테이지로 시작하기

1. `Tools > 맵 > 스테이지 에디터`에서 `Assets/Data/Stage/Expansion/CaptureTutorial.asset`(점령 연습)을 선택합니다.
2. 스테이지 에디터의 플레이 기능을 사용하거나, 전투 씬의 MapLoader > `기본 스테이지`에 이 에셋을 연결합니다. 다른 스테이지를 에디터에서 예약했다면 예약 스테이지가 우선합니다.
3. MapLoader > `씬 맵 처리 방식`은 `Replace`로 설정합니다. `UseSceneMap`이면 테스트 프리팹 대신 현재 씬의 맵을 사용하므로 그 맵에도 거점이 필요합니다.
4. `Assets/Data/Stage/Expansion/CaptureTutorial.prefab`을 열어 자식 `CapturePoint`를 확인합니다. 기존 1Stage를 상속한 변형 프리팹이며 원본 스테이지는 수정하지 않았습니다.
5. 테스트 거점은 월드 `(0, -1.2, 43)`, 반경 8입니다. 본부 배치 지점 `(0, -1.2, 61)` 앞쪽의 임시 위치입니다. Scene 뷰 기즈모로 원을 확인하고 실제 지면·NavMesh·이동 경로에 맞게 조정하세요.
6. 플레이어 유닛을 구역으로 보내 5초 점령합니다.

테스트용 설정은 최초 무리 배치를 비우고 낮을 600초로 늘렸습니다. 기존 맵의 스포너와 수비대는 남아 있습니다. 정식 튜토리얼의 난이도 조정까지 완료한 맵은 아닙니다. 로비 스테이지 목록과 전투 씬의 기본 맵은 자동으로 바꾸지 않았습니다. 테스트 클리어도 별도 스테이지 ID로 기존 보상 저장 흐름을 사용합니다.

## 새 스테이지 설정

스테이지 에디터 > 승리 조건:

- `승리 조건 덮어쓰기`: 켬.
- `거점 점령 승리 사용`: 켬.
- `점령 시간(초)`: 기본 5초, 0보다 큰 값.
- `생존 승리 사용`, `적 스포너 전멸 시 승리`: 점령 전용 미션에서는 끔.

여러 조건을 켜면 하나만 먼저 달성해도 승리합니다. 신규 옵션의 기본값은 꺼짐이므로 기존 스테이지의 승리 조건은 유지됩니다.

맵 프리팹의 MapRoot 아래에 빈 오브젝트를 만들고 **CapturePoint**를 붙입니다.

- `거점 이름`: 목표 UI에 표시할 이름.
- `점령 반경`: 월드 단위의 원 반경. Transform 스케일과 높이는 범위 판정에 영향을 주지 않습니다.
- Transform 위치: 점령 원의 중심. 다른 높이의 지형이 겹치지 않고 걸어서 접근할 수 있는 곳을 선택합니다.

활성 CapturePoint는 맵 안에 정확히 하나만 둡니다. 없거나 여러 개면 점령 판정을 시작하지 않고 오류를 안내합니다. MapLoader는 실제 사용 중인 맵의 거점을 연결합니다. MapLoader가 없는 테스트 씬에서는 GameResultManager의 `거점 점령 승리 사용`, `점령 시간(초)`, `점령 거점`을 직접 설정합니다. 플레이어 판정에는 같은 컴포넌트의 `플레이어 ID`를 사용합니다.

현재 전투 규칙과 동일하게 다른 소유자 ID는 적으로 간주합니다. 중립 오브젝트는 이 단계의 맵에 배치하지 마세요. 안개로 보이지 않는 적도 범위 안에 실제로 존재하면 점령을 막습니다.

## 목표 UI와 월드 표시 연결

VictoryConditionHUD에 기준 TMP 텍스트 하나를 연결하면 활성 승리 조건마다 복제한 텍스트가 자동 생성됩니다. 생성 순서는 생존 → 스포너 전멸 → 거점 점령이며, 사용하지 않는 조건은 숨깁니다. 기존 복제본은 재사용하므로 갱신할 때마다 늘어나지 않습니다.

1. TMP 텍스트 하나를 만들고 폰트·색상·크기·Layout Element를 원하는 모습으로 설정합니다.
2. **VictoryConditionHUD > 기준 텍스트**에 연결합니다. 씬 텍스트와 TMP 텍스트 프리팹을 모두 사용할 수 있습니다. 씬의 원본 텍스트는 플레이 중 숨기고 복제본만 표시합니다.
3. **조건 목록 부모**에 목록 컨테이너를 연결합니다. 비워두면 기준 텍스트의 부모를 사용합니다. 프리팹 에셋을 기준으로 쓰는 경우 부모도 반드시 연결합니다.
4. 목록 부모에 **Vertical Layout Group**을 붙이고 간격·정렬·자식 크기 조절을 에디터에서 설정합니다. 내용에 맞는 높이가 필요하면 Content Size Fitter를 함께 설정합니다. 여러 조건에 Layout Group이 없으면 텍스트가 같은 위치에 겹칠 수 있어 경고합니다.
5. HUD 컴포넌트는 기준 텍스트 자신이나 그 자식이 아닌 별도 관리 오브젝트에 붙입니다. 전체 패널을 숨기고 다시 표시하려면 HUD를 패널 밖에 두고 **모든 조건이 꺼졌을 때 숨길 오브젝트**에 패널을 연결합니다.
6. 기존 생존 조건 텍스트 참조는 기준 텍스트로 자동 승계합니다. 이전 스포너·점령 텍스트와 전용 묶음은 중복 표시되지 않도록 숨깁니다. 목록 부모와 HUD의 부모는 숨기지 않으므로, 이전 묶음에 장식이 남아 있다면 에디터에서 정리하세요.
7. Battle 씬에는 아래의 점령 위치 표시가 연결되어 있습니다. 다른 씬은 같은 표시 컴포넌트와 참조를 연결합니다.

코드는 기준 텍스트 복제, 문구 갱신과 활성 상태만 담당합니다. 폰트·색상·위치·간격을 덮어쓰거나 패널·Layout Group을 자동 생성하지 않습니다. 기준 텍스트가 없으면 경고하고 목록을 생성하지 않으며 점령 판정은 계속 동작합니다. 기준 텍스트와 목록 부모는 플레이 전에 연결하세요.

## 검증 기록과 플레이 확인

- `Tests/CapturePoint.Tests.ps1`: 실제 CapturePoint 소스를 최소 실행 대역과 함께 검증하며 17개 항목 통과. 진입·이탈·사망·적 진입·건물 구분·경계·정지·완료·잘못된 설정을 확인했습니다.
- 설치된 Unity의 컴파일러와 프로젝트 참조를 사용한 런타임·에디터 C# 컴파일: 오류 없음. 기존 파일의 미사용·미할당 필드 경고만 있습니다.
- 이 검증은 Unity 에디터의 프리팹 임포트, NavMesh 이동, UI 연결, 동시 본부 파괴 및 실제 보상 저장 플레이 검증을 대신하지 않습니다.

플레이에서는 2초 점령 후 적을 진입시켜 일시 정지되는지, 적을 제거하면 이어지는지, 아군이 전부 나가면 0초로 돌아가는지 확인하세요. 이후 완료 시 결과 창, 같은 프레임의 본부 파괴 우선 처리, 재시작 초기화와 기존 생존·스포너 전멸 미션도 확인하면 됩니다.

## 맵·미니맵의 점령 위치 표시

Battle 씬의 MiniMap 오브젝트에 CaptureMissionIndicator를 연결했습니다. 점령 미션에서 실제 연결된 CapturePoint의 위치를 자동으로 표시합니다. 다른 승리 조건만 사용하는 스테이지와 게임 종료 후에는 숨깁니다.

- 월드: 실제 점령 반경에 맞는 노란 원형 테두리입니다. 지면 높이는 테두리를 만들 때만 샘플링하며 매 프레임 다시 계산하지 않습니다.
- 미니맵: 노란 마름모입니다. 맵 가로세로 비율과 UI 크기에 맞는 좌표를 사용하며 미니맵 클릭을 막지 않습니다.
- 안개: 두 표시는 안개 밖에서도 보입니다. 목표 표시만 위에 그리며 주변 지형 탐색 기록이나 적의 가시성을 변경하지 않습니다. 월드 테두리는 목표 안내이므로 다른 물체 뒤에서도 보입니다.

CaptureMissionIndicator 인스펙터에서 `테두리 두께`, `테두리 분할 수`, `지면 높이 여유`를 조절합니다. 월드 색은 연결된 CaptureObjective 머티리얼의 `표시 색`에서 바꿉니다. 기본 카메라는 MainCamera이며 다른 카메라를 쓰면 `월드 표시 카메라`를 연결하세요. `월드 표시 레이어 번호`는 기본 0(Default)입니다.

미니맵 외형은 씬에 미리 배치한 MiniMap/CaptureObjectiveMarker의 Image 색과 RectTransform 크기·회전으로 조절합니다. 플레이 중 실제 MapArea 아래로 이동해 위치만 추적합니다. 코드는 UI를 생성하거나 외형 값을 덮어쓰지 않습니다.

다른 전투 씬에 사용할 때는 CaptureMissionIndicator의 `미니맵`, `미니맵 거점 표시`, `월드 표시 머티리얼`을 연결합니다. 표시 컴포넌트 자체를 숨길 대상 마커에 붙이지 마세요.

검증: C# 컴파일과 씬의 참조 연결 검사 통과. 실제 게임 화면에서는 점령 스테이지의 시작 위치 표시, 미니맵 클릭, 안개 밖 표시, 완료 시 숨김과 지형 경계의 테두리 높이를 확인하세요.

## 점령 진행 슬라이더

Battle 씬의 메인 Canvas에 CaptureProgressUI를 붙이고, 자식 CaptureProgressSlider를 연결했습니다. 점령을 시작하면 거점 위에 노란 진행 막대가 표시됩니다. 적 때문에 중단되면 값을 유지하고, 마지막 아군이 이탈해 초기화되면 0으로 돌아가며 숨깁니다. 게임 종료·다른 미션·설정 오류 때도 숨깁니다. 카메라 뒤나 화면 밖의 거점은 화면 가장자리에 잘못 표시하지 않습니다.

- CaptureProgressUI > `점령 진행 슬라이더`: 씬에 배치한 Slider 참조입니다.
- `거점 위치 따라가기`: 기본 켜짐. 끄면 직접 배치한 고정 HUD 위치에서 표시할 수 있습니다.
- `거점 기준 위치 차이`: 기본 `(0, 3, 0)`. 거점 위 표시 높이를 조절합니다.
- `월드 카메라`: 비우면 MainCamera를 사용합니다.
- CaptureProgressSlider의 RectTransform에서 너비·높이, Image에서 배경색, Fill의 Image에서 채우기 색을 조절합니다.
- Slider는 표시 전용으로 Interactable 꺼짐, Whole Numbers 꺼짐, 범위 0~1, Fill Rect 연결 상태입니다. UI의 Raycast Target도 꺼져 게임 명령 클릭을 막지 않습니다.

코드는 진행값·표시 여부·거점 추적 위치만 갱신합니다. 슬라이더를 런타임에 생성하거나 크기·색상·레이아웃을 덮어쓰지 않습니다. CaptureProgressUI는 숨겨질 슬라이더 자신이나 그 자식에 붙이지 마세요.

검증: C# 컴파일과 씬 연결 검사. 플레이에서는 진행·중단·이탈 초기화, 카메라 이동과 줌, 점령 완료 시 숨김을 확인하세요.
