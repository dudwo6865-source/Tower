# 맵 생성기 점검과 실행 취소 수정

## 요청과 점검 범위

Top 칠하기를 기존 바닥 범위로 제한하고, 실행 취소 후 바닥이 사라지는 문제를 점검했습니다. 칠하기·지우기·층 정리·언덕·램프·미리보기·설정 저장·생성 부모·타일 세트 생성·Undo/Redo·노멀 생성 경로를 확인했습니다.

기존 씬, 맵 프리팹, 타일 세트 자산은 변경하지 않았습니다. 이미 저장된 맵의 셀을 강제로 삭제하거나 이동하지 않습니다.

## 바닥 손실과 실행 취소의 구조

Top 칠하기는 바닥 위에 별도 오브젝트만 올리는 작업이 아닙니다. 같은 칸을 groundCells에서 제거하고 tops에 넣습니다. 주변 언덕·램프·윗층도 함께 정리할 수 있습니다. 따라서 Top만 되돌리는 것이 아니라 관련 목록 전체가 함께 돌아가야 합니다.

기존 창은 드래그 중 Undo.RecordObject로 매번 차이를 기록했고, 창을 그리는 OnGUI에서도 같은 컴포넌트의 기록을 예약했습니다. 스트로크의 시작·끝을 명시적으로 분리하지 않았으며, 실행 취소 후 타일 재생성은 열려 있는 창의 현재 대상에 의존했습니다. 이 흐름을 전체 데이터 스냅샷과 명시적인 스트로크 그룹으로 교체했습니다.

기존 방식의 단순 부분 기록 비교 테스트 역시 통과했으므로, 사용자가 보고한 특정 드래그 상황의 원인을 부분 기록 하나로 단정하지는 않습니다. 실제 사용자 맵에서 같은 입력을 재현한 것은 아닙니다. 새 방식에서는 바닥 49칸 중 3칸을 Top으로 바꾼 뒤 한 번의 Undo로 원래 바닥 목록과 49개 타일을 정확히 복원하는 것을 실제 Unity에서 확인했습니다.

별도로 확실히 확인한 바닥 손실 경로는 다음과 같습니다.

- `Top/Hill만 지우기`는 Top/Hill이 대체했던 바닥을 복원하지 않았습니다.
- 연결할 Top이 사라져 언덕이 자동 정리될 때 해당 칸의 바닥을 복원하지 않았습니다.
- 바닥 없는 빈 칸에도 새 Top을 칠할 수 있어, 그 Top을 실행 취소하면 돌려놓을 원래 바닥 자체가 없는 경우가 있었습니다.

## 반영한 수정

1. 새 Top은 Ground 데이터가 있는 칸에만 생성합니다. 빈 공간은 음수 층도 칠할 수 없습니다. 기존 Top의 높이 조절과 기존 윗층 지지 조건은 유지합니다.
2. 한 번의 드래그를 전체 데이터 스냅샷 하나로 기록하고 앞뒤 작업과 Undo 그룹을 분리합니다. 배치할 수 없는 Top 클릭은 빈 기록을 만들지 않습니다.
3. 창을 닫거나 다른 지형을 선택한 뒤에도 실행 취소된 지형의 타일을 다시 만듭니다. 다른 오브젝트의 Undo에는 변경 없는 맵을 재생성하지 않습니다.
4. Undo/Redo 재생성은 되돌린 지형 데이터를 추가로 정리하거나 수정하지 않습니다. 인스펙터의 수동 재생성·층 정리는 별도 전체 Undo 기록으로 보호합니다.
5. Alt를 누른 채 버튼을 놓는 경우, Esc로 마치는 경우, 페인트 OFF·대상 변경·창 종료도 스트로크를 마무리합니다.
6. 설정은 실제 값이 바뀔 때만 기록하고, 프리팹 인스턴스 변경과 씬 저장 상태도 표시합니다.
7. Top/Hill 일괄 삭제와 저층 언덕 정리는 원래 바닥을 복원합니다. 기본 Top 지우개로 음수 층 Top을 지우지 못하던 조건도 수정했습니다.
8. 큰 Top 브러시가 맵 밖으로 걸치면 빈 칸은 개별적으로 빨갛게 표시하고 건너뜁니다.
9. 바닥 없는 방향이나 지하 Top에서 사용할 수 없는 램프를 새로 기록하지 않으며, 같은 램프를 다시 찍는 것은 변경으로 처리하지 않습니다.
10. 생성 부모는 페인터 아래에 `지형`이라는 이름으로 자동 생성합니다. 기존 `Generated` 전용 부모는 재사용하며, 맵 루트가 잘못 연결되어 있어도 루트 전체를 삭제 대상으로 사용하지 않습니다.
11. 기본 타일 세트 생성의 오래된 프리팹 경로를 현재 폴더 우선으로 수정했습니다. 벽은 Wall → Wall1 순서로 찾고, 직선 언덕 연결은 WXH를 연결합니다. 과거 경로도 대체 검색합니다.
12. 필요한 Top·바닥·램프·언덕 프리팹이 없는 칠하기는 안내 후 중단합니다. 데이터만 바뀌고 타일이 보이지 않는 상황을 방지합니다.

기존 Top 아래에는 Ground 데이터가 남지 않는 구조이므로, 기존 Top의 높이 편집에는 Ground 존재를 요구하지 않습니다. 자동 벽이 차지하는 칸은 바닥 메시가 생략되어도 Ground 데이터가 남아 있으면 기존 바닥 영역으로 인정합니다.

## 후속 개선 권장

### 우선순위 높음 — 노멀 에셋 생성 분리

경계 노멀 연결을 켜면 재생성마다 새 MapNormals 에셋을 만들고 저장합니다. 이전 에셋은 다른 맵이 참조할 수 있어 자동 삭제하지 않습니다. 반복 칠하기나 Undo로 미사용 에셋과 저장 시간이 누적될 수 있습니다.

편집 중에는 임시 메시로 미리 보고, 명시적인 맵 저장 단계에서 노멀 에셋을 확정하는 방식이 좋습니다. 기존 에셋 정리는 참조 검사가 필요하므로 이번에는 자동 삭제하지 않았습니다.

### 우선순위 중간 — 변경 영역만 재생성

현재는 마우스를 놓을 때 생성 부모 아래의 모든 타일을 삭제하고 다시 만듭니다. 큰 맵에서는 인스턴스 생성·정적 설정·노멀 계산 비용이 커집니다. 변경 칸과 주변 연결 타일, 영향을 받는 윗층만 갱신하도록 나누는 것을 권장합니다.

### 우선순위 중간 — NavMesh 갱신 안내

지형 타일 재생성과 NavMesh 굽기는 별도입니다. 미리 구운 NavMesh를 사용하는 맵은 편집 후 이전 경로 데이터가 남을 수 있습니다. 맵 생성기에 경로 데이터의 변경 상태와 재굽기 버튼을 연결하면 실수를 줄일 수 있습니다. 현재는 지형 수정 후 기존 스테이지 편집 도구에서 NavMesh를 다시 굽고 확인합니다.

### 우선순위 중간 — 높이별 작업 평면

언덕은 실제 표면을 찾지만 Top/바닥 브러시는 기본 높이 평면으로 칸을 계산합니다. 기울어진 시점에서 높은 층을 편집할 때 마우스 위치와 표시 위치가 어긋나 보일 수 있습니다. 기본 격자 기준/선택 층 기준 작업 평면을 고를 수 있게 개선하는 것을 권장합니다.

`지형`(기존 `Generated`) 아래에는 수동으로 만든 본부·건물·장식을 넣지 마세요. 이 폴더는 재생성 시 자식을 모두 교체하는 전용 영역입니다.

## 검증

`Tests/Run-CliffPainterRegression.ps1`은 별도 임시 Unity 2022.3.26f1 프로젝트에 실제 코드를 복사해 검증합니다. 작업 중인 프로젝트·씬·Undo 기록을 사용하지 않습니다.

33개 검증 항목: 빈 공간 배치 거절, 바닥 대체, 다중 칸 Undo/Redo, 실제 바닥 메시 복원, 별도 스트로크 분리, 언덕 자동 정리와 일괄 삭제의 바닥 복원, 지하 지형 삭제·높이 변경, 윗층 지지 조건, 램프 배치와 중복, 맵 경계, 다른 오브젝트 Undo의 맵 재생성 방지, 생성 부모 이름·기존 부모 재사용·외부 부모 재사용·자기 참조 복구·잘못 연결된 맵 루트의 본부 보존.

마우스 드래그·Alt 해제·창 전환의 실제 GUI 조작과 사용자 맵의 외형·NavMesh는 유니티에서 추가 확인합니다. 셀 규칙과 Undo/Redo 자체는 실제 에디터 배치 실행으로 검증합니다.
