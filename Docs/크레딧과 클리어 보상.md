# 크레딧과 클리어 보상

크레딧은 스테이지의 마석과 별개인 영구 재화입니다. 승리가 결정되는 순간 자동 저장하며, 패배하거나 결과 창을 다시 여는 것으로는 지급하지 않습니다. 영구 연구와 소비 기능은 아직 포함하지 않습니다.

## 스테이지 설정

`Tools > 맵 > 스테이지 에디터`에서 스테이지를 고르고 **크레딧 / 클리어 등급 > 클리어 보상**을 펼칩니다. MapConfig 인스펙터에서도 같은 설정을 바꿀 수 있습니다.

승리 방식과 관계없이 세 항목을 점수로 합산합니다.

- 시간 점수 = 게임 시간(초) × 초당 점수. 기본 배율 1.
- 스포너 점수 = 파괴한 적 스포너 수 × 개당 점수. 기본 배율 100.
- 마석 점수 = 실제 누적 마석 획득량 × 개당 점수. 기본 배율 1.

항목별 소수점 이하는 버린 후 합산합니다. 오래 플레이하고, 스포너를 많이 파괴하고, 마석을 많이 획득할수록 점수가 증가합니다. 시간은 일시정지를 제외한 게임 내 시간이며 결과가 결정된 순간 집계를 멈춥니다. 시작 마석은 제외하며, 획득한 마석을 소비해도 누적량은 줄지 않습니다. 보유 상한 때문에 실제로 얻지 못한 마석은 제외합니다.

**기준 점수** 기본값은 1,000이며, 배율과 함께 스테이지별로 조절합니다.

- 기준 점수의 50% 미만: 0성.
- 50% 이상: 1성. 기본 500점.
- 75% 이상: 2성. 기본 750점.
- 100% 이상: 3성. 기본 1,000점.

별 기준이 소수이면 다음 정수부터 달성합니다. 예를 들어 기준 1,001점의 1성은 501점, 2성은 751점입니다. 기준을 넘겨도 최대 3성입니다. 기본 설정에서 게임 시간 300초 + 스포너 4개 + 마석 300개면 300 + 400 + 300 = 1,000점으로 3성입니다.

클리어 자체로 별을 지급하지 않으며, 0성 보상은 0 크레딧입니다. 패배에는 별과 크레딧을 지급하지 않습니다. 기존 저장의 크레딧과 최고 별 기록은 유지합니다. 본부 누적 피해와 버틴 웨이브는 통계만 유지하며 점수에 영향을 주지 않습니다.

최초 보너스는 각 별을 처음 얻을 때 한 번씩 지급합니다. 기본값은 별 1개 100, 두 번째 별 50, 세 번째 별 50입니다. 반복 보상은 그 판의 등급에 따라 20 / 30 / 40 중 하나를 지급하며 첫 클리어에도 포함됩니다.

- 첫 클리어 1성: 100 + 20 = 120 크레딧.
- 이후 3성으로 기록 갱신: 50 + 50 + 40 = 140 크레딧.
- 이후 3성 재클리어: 40 크레딧.
- 처음부터 3성 클리어: 100 + 50 + 50 + 40 = 240 크레딧.

스테이지 에셋의 GUID를 저장 식별자로 사용합니다. 에셋 이름과 위치를 바꿔도 기록은 유지되며, 복제한 스테이지는 새로운 기록을 사용합니다. `.meta` 파일을 보존해야 합니다. MapLoader 없이 실행하는 씬에는 영구 보상을 지급하지 않습니다.

## 화면 연결

Battle 씬 결과 창에는 게임 시간·파괴한 스포너·획득한 마석 세 줄을 표시합니다. 각 값은 `실적 × 배율 = 점수`로 표시하며 소모한 와트 줄은 종합점수 영역으로 대체했습니다.

종합점수는 0부터 최종값까지 기본 2.2초 동안 올라갑니다. 같은 값으로 슬라이더가 차오르고 1·2·3성 기준에 도달하면 게이지가 동색·은색·금색으로 바뀝니다. 기준 위치에 별 이미지가 나타나며 짧게 확대됩니다. 결과 창의 일시정지 중에도 재생하며, 최종 점수가 기준보다 크면 숫자는 계속 올라가고 게이지만 100%에 고정됩니다. 패배 시에는 성적만 표시하고 별과 크레딧은 지급하지 않습니다.

Hierarchy의 `WinPanel > Game Statistics > inventory > 종합점수`에 붙은 **ResultScoreUI**에서 상승 시간·별 등장 시간·확대 배율·색·글자 크기를 조절합니다. 텍스트·슬라이더·별 이미지 연결이 없으면 실행 시 자동 생성합니다. 별 스프라이트를 지정하지 않으면 오각별 모양을 생성하며, 원하는 스프라이트로 교체할 수 있습니다. 직접 UI를 배치하면 해당 필드에 연결합니다.

GameResultUI의 **점수 연출 UI**가 해당 컴포넌트를 참조합니다. 실제 지급은 승리 확정 시 이미 저장되므로 연출을 다시 보거나 중간에 로비로 이동해도 보상이 중복되거나 사라지지 않습니다. UI에 표시되는 배율과 기준도 결과 확정 시점의 설정을 사용합니다.

로비에서는 보유량을 표시할 TMP 텍스트에 **CreditHUD**를 붙입니다. 같은 오브젝트의 텍스트를 자동으로 연결합니다. **표시 형식** 기본값은 `크레딧 {0:N0}`이며, 숫자만 표시하려면 `{0:N0}`으로 바꿉니다. 기존 로비 씬의 편집 내용은 변경하지 않습니다.

## 저장 및 검증

`Application.persistentDataPath/credit-progress.json`에 보유 크레딧과 스테이지별 최고 등급을 함께 저장합니다. 임시 파일을 쓴 뒤 기존 파일을 교체하며 이전 파일은 `.bak`으로 남깁니다. 저장에 실패하면 잔액과 최초 달성 기록을 변경하지 않습니다. 결과 창의 재침공 또는 함선으로 버튼을 누르면 저장을 재시도하며, 성공해야 이동합니다. 손상된 저장 파일을 자동으로 초기화하지 않습니다.

`Tests/Test-CreditRewards.ps1`은 임시 저장 경로에서 보상 계산, 중복 방지, 기록 향상, 재실행, 저장 실패와 재시도, 손상 파일 보호를 확인합니다. 유니티 API와 JSON 직렬화는 테스트 대체 구현을 사용하므로 실제 유니티 화면과 직렬화 동작 확인은 별도로 필요합니다.
